<objective>
To establish the database schema, RLS policies, storage buckets, and TypeScript types for the course management hierarchy. This foundation is necessary before any UI components can fetch or mutate data.
</objective>

<context>
- We need 4 tables: `courses`, `chapters`, `lessons`, and `enrollments`.
- The storage bucket `assignments` must be created.
- Admin needs full access, students need read access to enrolled content.
</context>

<tasks>
1. Create SQL migration for schema structure and triggers
   - Create tables: `courses`, `chapters`, `lessons`, `enrollments`.
   - Set up foreign keys with proper `ON DELETE CASCADE`.
   - Ensure `order_index` is present in chapters and lessons.
2. Create SQL migration for RLS policies
   - Enable RLS on all 4 tables.
   - Admin (`auth.users()`) has `ALL` on all tables.
   - Student has `SELECT` on courses, chapters, lessons if they possess a matching `enrollments` record.
   - Student has `SELECT` on enrollments where `user_id = auth.uid()`.
3. Create SQL migration for Storage Bucket
   - Initialize `assignments` storage bucket.
   - Set bucket policies: Authenticated can upload (admin), read.
4. Export TypeScript types
   - Update `src/types/database.types.ts` (if using Supabase codegen) or create `src/types/course.ts` containing the TS interfaces for `Course`, `Chapter`, `Lesson`, `Enrollment`.
</tasks>
