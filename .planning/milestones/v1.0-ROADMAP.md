# Milestone v1.0: BuMath LMS MVP

**Status:** ✅ SHIPPED 2026-05-01
**Phases:** 1–8
**Total Plans:** 38

## Overview

BuMath v1.0 evolves a static marketing landing page into a full async LMS for Vietnamese math education (grades 7–9 + advanced). The milestone delivered: production infrastructure, user auth with role-based access, admin course management, student learning and submission, teacher grading and notifications, UX polish, auth security hardening, and teacher role access.

## Milestone Summary

**Key Decisions:**
- Supabase as full-stack backend (Auth + DB + Storage + RLS) — validated, no issues
- YouTube embed for video content — validated, works well for MVP
- Photo upload + manual grading model — validated, fits Vietnamese handwritten math assignments
- Admin approval gate for student accounts — validated, provides quality control
- GRADE-04 scope adjustment: email notification deferred, in-app bell delivered — accepted
- ProtectedRoute `allowedRoles` API: teacher/admin share grading routes via array over string — clean backward-compatible extension

**Issues Resolved:**
- Teacher role had zero accessible routes (critical gap from audit) — fixed by Phase 8
- Pending students weren't redirected to /pending after login — fixed by Phase 7
- AdminLayout had no logout button — fixed by Phase 7
- Student data isolation (profiles RLS) was never implemented — fixed by Phase 7
- Register flow had NaN year error and post-signup flicker — fixed in Phase 8 context

**Issues Deferred to v2:**
- Email notifications for graded submissions (GRADE-04 original requirement text)
- Supabase free-tier pause heartbeat — operational concern for v2
- BellNotification uses 60s polling instead of Realtime subscription

**Technical Debt Incurred:**
- `requireApproved` prop in ProtectedRoute is dead code (defaults to false, no route uses it)
- `GRADE_BADGE` constant duplicated in `UserEnrollmentDialog.tsx` instead of importing from `@/lib/constants/grades`
- Hardcoded `ADMIN_ZALO_NUMBER` in Pending.tsx — should be env var
- Phase 2 VERIFICATION.md still shows `gaps_found` despite all gaps resolved by 02-04/02-05
- Vercel deployment and deep-link routing require live-env human verification
